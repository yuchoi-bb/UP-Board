# UP-Board 설계

개인용 포털 웹서비스. 여행 계획과 직접 만든 웹앱 링크를 "토픽"으로 모아 관리한다.
혼자 쓰는 서비스이며 계정은 본인 1개만 허용한다.

## 구성

| 항목 | 결정 |
| --- | --- |
| 저장소 | `UP-Board` |
| 호스팅·백엔드 | Firebase (Hosting, Firestore, Functions, FCM) |
| 도메인 | Firebase 기본 도메인(`<project>.web.app`)으로 시작 |
| 로그인(모바일) | 패스키(WebAuthn) 지문 |
| 로그인(PC) | FavHub 앱으로 푸시 → 지문 승인 |
| 콘텐츠 편집 | 사이트 안에서 직접 편집 + Gemini 채팅 |

패스키는 도메인에 묶인다. 나중에 커스텀 도메인으로 옮기면 지문을 1회 다시 등록해야 한다.

## 토픽

여행 계획, 앱 링크, 메모를 구분하지 않고 전부 "토픽"이라고 부른다.

- 트리 구조: 토픽 아래에 서브토픽을 둘 수 있다.
- 토픽 하나는 제목, 내용(마크다운), 링크 목록을 가진다.
- 여행 토픽 밑에서 여행 관련 웹앱을 새로 코딩하면, 그 앱은 해당 토픽의 서브토픽(링크)으로 붙인다.

Firestore 구조:

```
topics/{topicId}
  title, content, links[{label, url}], parentId, order,
  createdAt, updatedAt, updatedBy("me" | "ai"), updatedSummary, turnId, deletedAt
topics/{topicId}/versions/{versionId}
  title, content, links[], author("me" | "ai"), summary, turnId,
  createdAt(그 상태가 만들어진 시각), archivedAt(이력으로 밀려난 시각)
```

인증 데이터(`auth/*`, `authCredentials`, `authChallenges`)는 Firestore 규칙으로 전부 막고
Functions의 Admin SDK로만 다룬다.

## 로그인

### 모바일

패스키로 지문 로그인한다. Functions가 WebAuthn 검증을 하고 Firebase 커스텀 토큰을 발급한다.
계정은 고정 UID `owner` 하나뿐이다.

첫 패스키 등록은 배포할 때 정한 설정 코드(`SETUP_CODE`)를 알아야만 할 수 있다.
주소를 먼저 알아낸 남이 사이트를 차지하지 못하게 하기 위한 것으로, 설정이 끝나면 다시 쓸 수 없다.

### PC

1. PC에서 "폰으로 로그인"을 누르면 Functions가 로그인 요청(난수, 만료 2분)을 만든다.
2. FCM으로 FavHub 앱에 푸시를 보낸다.
3. 앱이 요청 내용(시각, 브라우저, 확인 숫자)을 보여주고 지문(BiometricPrompt)으로 승인받는다.
4. 앱은 미리 등록해 둔 기기 키로 승인에 서명해 보낸다. 서명이 맞아야만 PC에 세션이 발급된다.
5. PC는 요청 문서를 지켜보다가 승인되면 자동 로그인한다.

기기 키는 로그인된 폰에서 1회 페어링해 등록한다. PC 화면과 폰 화면에 같은 확인 숫자를 띄워,
남이 보낸 요청을 실수로 승인하지 않게 한다.

### 복구 (폰 분실·교체)

로그인이 전부 폰에 걸려 있으므로 두 겹으로 대비한다.

- **동기화 패스키**: 패스키를 기기 전용이 아니라 구글 계정에 동기화되는 방식으로 등록한다.
  같은 구글 계정으로 새 폰을 설정하면 지문 로그인이 그대로 복원된다.
- **복구 코드**: 최초 설정 때 일회용 복구 코드 10개를 한 번만 보여준다. 서버에는 해시만 저장한다.
  복구 코드로 들어가면 새 패스키를 등록하고, 기존 패스키·기기 키·세션은 전부 폐기할 수 있다.
  코드는 쓰면 소멸하고, 설정 화면에서 전체 재발급할 수 있다.

FavHub 기기 키는 폰에 묶여 있어 동기화되지 않는다. 새 폰에서는 페어링을 다시 한다.

## 변경 이력과 되돌리기

Gemini가 토픽을 직접 고치므로, 모든 수정은 되돌릴 수 있어야 한다.

- 토픽을 저장할 때마다 직전 상태를 `versions`에 남긴다. 직접 편집과 AI 편집 모두 해당한다.
- AI 편집은 채팅 한 턴에서 일어난 변경을 `turnId`로 묶는다. "되돌리기" 한 번으로 그 턴의 변경이
  여러 토픽에 걸쳐 있어도 전부 원복된다.
- 이력 화면에서 누가(나 / AI), 언제, 무엇을 바꿨는지 보고 원하는 버전으로 복원한다.
  복원도 새 버전으로 기록되므로 복원 자체를 다시 되돌릴 수 있다.
- 토픽당 최근 50개 버전을 보관한다.
- 토픽 삭제는 즉시 지우지 않고 휴지통으로 보낸다. AI가 삭제한 것도 같은 방식으로 되살린다.

## Gemini 채팅

토픽 페이지에 채팅 패널을 둔다. "오사카 3박4일 일정 짜줘"로 내용을 생성하고,
"2일차 숙소 바꿔줘"로 그 자리에서 수정한다.

- Gemini API 키는 Functions에만 두고 브라우저에 노출하지 않는다.
- function calling 도구: 토픽 읽기, 토픽 수정, 서브토픽 생성.
- AI가 쓸 수 있는 범위는 현재 토픽과 그 하위 토픽으로 제한한다.

## 작업 순서

1. 스캐폴드, 토픽 트리 편집, 변경 이력, 모바일 패스키 로그인, 복구 코드
2. PC 푸시 승인 (FavHub 앱에 FCM 수신과 지문 승인 화면 추가)
3. Gemini 채팅 (AI 편집 턴 단위 되돌리기 포함)
